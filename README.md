# 個人直播台

靜態 HTML / JavaScript 網站，可部署到 GitHub Pages 或 Cloudflare Pages。

## 首頁密碼登入

- 首頁顯示登入畫面，密碼正確後才載入播放器、聊天室及頻道清單。
- 同一分頁重新整理會保留登入狀態；按「登出」會清除狀態並重新載入。
- 密碼設定只保存 salt 和 SHA-256 雜湊，不包含明文密碼。
- 這是阻擋一般訪客的前端密碼閘，不是私人託管。其他 HTML 頁面、公開檔案、程式庫和歷史版本仍可直接讀取。

### 檔案

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 首頁樣式、登入表單、登入後才掛載的網站模板 |
| `login.js` | 密碼驗證、啟動網站、同分頁登入狀態及登出 |
| `login.css` | 桌面與手機登入畫面 |
| `login-config.js` | 密碼 salt、雜湊及登入狀態名稱 |
| `tv-app.js` | 原有直播台功能，改為登入後啟動 |
| `set-login-password.cjs` | 更新密碼設定的 Node.js 工具 |

### 更改密碼

在專案根目錄執行：

```sh
node set-login-password.cjs
```

依提示輸入新密碼。也可以產生新密碼：

```sh
node set-login-password.cjs --generate
```

產生的密碼只會顯示在執行工具的終端。提交並部署更新後的 `login-config.js`，現有登入狀態會失效。請用網站專用密碼。

## GitHub Pages

在專案的 **Settings → Pages → Build and deployment** 設定：

- Source：**Deploy from a branch**
- Branch：**main**
- Folder：**/(root)**

儲存並等待部署完成後，使用原有 `https://umininn-gh.github.io/tv/` 網址。

## 聊天室

首頁預設載入本程式庫的 `test3.html`，並以匿名模式接收 Twitch `whitewing940920` 的訊息。這與 [SK 雞友直播台](https://skknower.com/user/ctvhiki49713?ch=12) 的右側 SKChat 使用相同的 Twitch 頻道；貼圖、回覆圖示和本地資源清單改從本網站讀取，不依賴已關閉的 chicktv GitHub Pages。

頂欄的 TWITCH 切換仍可開啟同頻道的 Twitch 官方聊天室，並記住選擇。目前先修復觀看訊息；自訂聊天室的 Twitch 發言登入尚未重新設定或驗證。

即時收訊會逐則解析 Twitch IRC，支援短留言省略內容前冒號的合法格式，也避免同批收到多則留言或控制訊息時漏顯示。歷史與即時留言按時間排列、避免重複，並保留 Twitch 回覆與自訂引用；循環引用會顯示提示，格式轉換失敗則保留原文。文字中的 HTML 符號按原文字顯示，貼圖和媒體由程式另外產生。

初次開頁顯示最近最多 30 則歷史留言。每按一次「載入更早留言」，再加入最多 30 則較早留言。`test3.html` 的 `CHAT_HISTORY_BATCH_SIZE` 統一設定首次及每次載入數量；正常跟隨最新留言時，畫面和背景緩衝的保留上限由該數量乘以 10 得出，目前為 300 則。閱讀舊留言期間暫停移走內容，可以超過 300 則，亦可繼續每次載入 30 則舊留言。重新連線或回到分頁時最多補抓 800 筆，只補已看過時間之後的訊息，不會自動加入大量更早紀錄。能補回的內容仍取決於外部服務保存的紀錄，不能保證與 SKLive 完全相同。

向上捲動、載入更早留言或跳到引用留言時，停止追底並暫停移走舊留言，背景緩衝也會保留暫停期間的訊息。手動捲回最底可跟隨新留言，但不解除保留暫停，右下角箭嘴仍會顯示。只有按箭嘴回到最新後，才解除暫停、移走超出上限的較早留言，保留最近 300 則，並恢復後續移除。加入、補回及重繪留言時會維持當前閱讀位置，媒體載入也不會強制追底。重新整理頁面則從最近 30 則重新開始。

右下角箭嘴會累計閱讀暫停期間新接收的未讀留言，按箭嘴回到最新後清零；手動捲到底部不清零。首次歷史和載入更早留言不計入，重連補回的新留言會去重後累計，背景接收、重新顯示及舊請求回應也不會重複計數。

登入按鈕放在底部媒體工具列右側，較小的設定齒輪位於載入更早留言左側。媒體工具列和輸入框預設收起，底部只保留薄的箭嘴列以展開／收起；草稿會保留，選擇回覆或插入引用時會自動展開。輸入框高度由約 52px 縮至 35px，各聊天主題的留言間距亦已收窄。

徽章與貼圖資源獨立載入並有逾時限制，不會阻擋歷史或即時留言。失效的 Twitch 登入資料會自動切回匿名觀看；重建連線時，舊連線的延遲事件不會中斷新連線。

## 直播台清單

原先 35 台保留 31 台，移除 4 個已無法使用的入口：Kick 的 `wing36747`、`no25no25`、`cobra-and-godzilla`，以及 Twitch 的 `no25no2501`。同 ID 的 Kick 和 Gosh 台仍然有效，分別保留。43 筆舊記錄中補回 17 台；另外 21 筆目前失效、2 筆是完整網址與 ID 的重複、1 個是已結束活動的 YouTube 存檔，2 筆無法確認。另從原程式的 whitewing918 公開清單和使用者提供的線索，補回 Twitch 的 G／OurChickenLife、RachelW 和 TristaLiveTV。

`channel-validation.json` 保存全部 81 筆來源記錄的逐筆結果、動作和官方證據；`channel-recovery.json` 保存還原來源及原來 43 筆舊記錄。AngelThump `ppkkkpp` 的官方 API 重試仍回覆 500，GoodGame `219534` 連線逾時；兩者暫緩加入，沒有當作已刪除。有效但離線的帳戶保留；若開啟「隱藏離線」，這些按鈕會暫時隱藏。

清單以「平台 + 頻道 ID」去重，完整 Twitch／YouTube 網址先轉成 ID，保留同名不同 ID 或不同平台的台。Gosh 保存頻道 ID，播放時再取得最新串流網址。已核查失效的 25 個入口也會從載入的瀏覽器舊清單中排除，原始儲存及備份保留。廣州電視的舊 HLS 入口已驗證直播片段和本站網域的跨來源播放權限，並改用較清楚的名稱，與雞舍台 G 分開。

瀏覽器已有的 `customChannels1` 自訂清單優先於預設清單；舊版 `customChannels` 會合併匯入一次，保留原始儲存備份。刪除的台會維持刪除，手動加回後才重新顯示。網絡暫時失效時使用上次成功載入的清單。只存在已清除的瀏覽器儲存、沒有進入 GitHub 的項目，無法由 Git 歷史找回。

## 多台播放

增減選台時，仍被選中的播放器會繼續播放，只建立新增的台、釋放移除的台。改變排列使用 CSS 排序，同一模式內保留 iframe 的連線及原有播放器的音量、暫停狀態；「看更台」會預先勾選正在播放的台。首頁切換單台與多台模式時，沿用原本的自動靜音規則。播放失敗的台再次選取時會重試。管理頁也支援補回的 Vaughn FLV 台，沿用相同的保留、釋放及重試行為。

直播狀態查詢會合併同一台的重複請求，同時最多執行 4 個查詢，並在 30 秒內沿用已取得的狀態。Gosh 的狀態與播放網址查詢只合併尚未完成的請求，避免反覆使用已失效的臨時網址。管理頁調整視窗大小只重畫狀態標示。

這主要改善增減直播台時的中斷與載入尖峰；穩定播放多台時，瀏覽器仍需要同時解碼各路直播。

首頁開始同時觀看至少兩台後，在「看更台」按「調整播放器位置」，即可拖曳到另一格或點選兩格交換位置。方向鍵也可搬位，按「完成搬位」或 Esc 恢復播放器操作。交換只修改 CSS 排列，不搬移或重建播放器，保留音量、靜音與暫停狀態；排列記錄在目前瀏覽器，重新選台及重新載入後仍會沿用。操作層只在搬位模式中監察尺寸，會跟隨手機影片／聊天分隔條調整。

主頁 M3U8／Gosh 使用 HLS.js 的 `capLevelToPlayerSize: true`，已有持續按影片元素尺寸限制自動畫質的功能；只有來源提供多種畫質時才可降低解像度。它也會考慮螢幕像素比例及網絡頻寬。原生 HLS 由瀏覽器處理；YouTube 等 iframe 由各平台控制畫質，Vaughn FLV 是單一來源。尺寸變更時的偵測通常開銷很小，降低小窗畫質可減少下載與解碼負擔；反覆強制切換畫質或重建播放器則可能增加緩衝。參考 [HLS.js 設定文件](https://github.com/video-dev/hls.js/blob/v1.7.3/docs/API.md#capleveltoplayersize)。

主頁及管理頁的 Twitch 使用官方互動播放器。多台同播時，按可見影片的 CSS 尺寸選擇最低足夠解像度，同解像度優先較低幀率，避免高 DPI 螢幕令小窗仍載入高畫質。尺寸變更會防抖，只有需要的畫質改變時才送出指令；搬位不會重建播放器。單台及全螢幕恢復 Twitch Auto。固定畫質會取代平台按網速選擇的 Auto，因此只在多台固定畫質期間每 5 秒檢查播放器已提供的緩衝統計；持續緩衝不足便退回 Auto，直至尺寸或觀看模式明顯變更。這項檢查不輪詢播放器尺寸，也不另行查詢 Twitch API。只有來源畫質或無法讀取畫質清單時保留 Auto，SDK 載入失敗則回退原 iframe。參考 [Twitch 官方播放器 API](https://dev.twitch.tv/docs/embed/video-and-clips/)。

Kick 的官方 iframe 只有播放、靜音及全螢幕參數，沒有公開的外部畫質控制接口。目前保留原有放大再縮回的方式：直接按小窗尺寸嵌入會轉用缺少音量控制的手機介面，跨越尺寸界線也可能改變靜音狀態。本站因此不強制調整 Kick 解像度，由平台自動畫質處理。參考 [Kick 官方嵌入說明](https://help.kick.com/en/articles/8010826-how-to-embed-your-kick-livestream)。

## 之後搬到 Cloudflare Pages

登入與播放器程式仍可沿用，不需要重寫整個網站。Cloudflare Pages 支援直接部署靜態 HTML：

1. 在 **Workers & Pages → Create application → Pages** 匯入這個 GitHub 程式庫。
2. Production branch 選擇 `main`，Framework preset 選擇 `None`。
3. Build command 使用 `exit 0`；Build output directory 使用 `.`（網站位於程式庫根目錄）。
4. 先確認直播與聊天室正常，再替正式網址及預覽網址配置 Cloudflare Access。
5. 若要真正私人使用，停用公開的 GitHub Pages，並另外處理公開程式庫與歷史頁面的可見性。

新增的登入資源與頻道清單使用相對路徑，同時支援 GitHub 的 `/tv/` 子路徑與 Cloudflare 的根網址。播放器仍依賴外部直播平台、代理與 Firebase；搬移時需要逐一確認這些外部來源仍可用，或改成自己的來源。Twitch 的 `parent` 已依目前網域產生。

官方文件：[Static HTML](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/)、[Preview deployments / Access](https://developers.cloudflare.com/pages/configuration/preview-deployments/)。
