# Umininn TV 播放器控制擴充功能（測試版）

1.0.0 發行套件的建置、Mozilla 簽署及正式安裝方式見 [RELEASE.zh-HK.md](RELEASE.zh-HK.md)。本文件保留 0.1.x 開發測試流程及驗證記錄。

這是供 Chrome、Edge 及 Firefox 手動載入的測試版。它在 Umininn TV 加入播放器控制列，透過擴充功能在獲授權的播放器頁面內調整影片音量、靜音及嘗試恢復播放。它不會改動網站部署，也未上架任何擴充功能商店。

## 0.1.6 修正

移除整批一起等待的限制：每台就緒狀態各自穩定 600ms 後，便加入本輪檢查／恢復佇列，讓已就緒的台先處理。其餘台繼續獨立等待，載入期限最多 30 秒；期限內，每秒重新詢問尚未就緒的 iframe 狀態，並顯示仍在等待的台數。每台仍只嘗試恢復一次，同時最多 4 項操作。

已確認舊有整批等待條件會令已就緒的台被其他台拖延；這不代表所有延遲都來自同一原因，也不將問題歸為 Firefox 或混合平台獨有。播放器台數、尺寸及平台自動播放行為仍可能影響結果。

## 0.1.5 修正

頂部新增「↻ 偵測恢復」，控制選單亦有同一按鈕。一按會掃描目前播放器、逐台重新讀取狀態，再對未播放而可控制的台各嘗試恢復一次；已播放或正在緩衝的台會略過。同時最多執行 4 項操作，這輪不調整音量／靜音、不重載播放器，也不在背景持續重試或監控暫停狀態。

在「看更台」按「開始觀看」，會先讓原網站完成選台，再等待本輪播放器，包括仍未插入 iframe 的 Twitch 容器、iframe 回應及原生影片 metadata。就緒狀態穩定 600ms 後執行一輪，載入等候最多 30 秒；不支援或未就緒的台會如實列出。新的「開始觀看」會取消上輪；一般搬位、調整尺寸或開啟選單不會觸發恢復。

## 0.1.4 修正

加入只用於已知 HTTPS Twitch iframe 的手動播放流程。按「恢復播放」時，優先尋找唯一、可見且明確標示 Play 的平台覆蓋層按鈕，沒有覆蓋層才考慮工具列 Play；每次請求最多點一次，不盲按可能已變成 Pause 的切換鍵。平台尚未建立影片元素時，也可透過這個 Play 按鈕啟動。沒有可信的 Play 按鈕時，沿用原生影片播放請求。

按鈕點擊完成不代表恢復成功，必須觀察到原生影片實際播放才回報成功；等候逾時不會暫停影片。0.1.4 其後收到使用者回報，Chrome／Edge／Firefox 均通過使用；這不代表所有頻道或後續版本均已實測。

## 0.1.3 修正

修正 Firefox 沒有顯示控制按鈕：content script 的 `globalThis` 與 `window` 不相等，舊判斷令介面不啟動。新版用實際 `window` 判斷頂層頁面與操作 DOM，設定、控制器及 runtime 保留在隔離全域。[Mozilla 官方相容性說明](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Chrome_incompatibilities#content_script_environment)

新增 4 項啟動模型回歸：Firefox sandbox、Chrome Window、子頁框，以及不受信任頁面／缺 runtime／已有介面的限制。Firefox 模型在修正前失敗、修正後通過。

## 0.1.2 修正

修正手動恢復播放等候超過 3 秒後，擴充功能主動暫停影片的問題。未能在確認期限內收到播放訊號時，仍會回報未確認／等待，不再因這次等候逾時而呼叫暫停；影片稍後開始播放時，可以接續更新播放狀態。

## 0.1.1 修正

修正按下「🎚 播放控制」後選單被網站頂欄裁切，看起來沒有反應的問題。按鈕仍在頂欄，選單改掛在頁面主體，讓選單可以完整顯示。

## 建立安裝包

在程式庫根目錄執行：

```powershell
node --test "tests/player-extension-*.test.cjs"
node tools/build-player-extension.cjs
```

不需要安裝 npm 套件。輸出位於 `outputs/player-extension/`：

| 瀏覽器 | 可載入資料夾 | ZIP 壓縮檔 |
| --- | --- | --- |
| Chrome 109 或以上 | `chrome/` | `chrome.zip` |
| Edge 109 或以上 | `edge/` | `edge.zip` |
| Firefox 140 或以上 | `firefox/` | `firefox.zip` |

ZIP 內的根目錄就是 `manifest.json`。先解壓到固定位置，再依下列步驟載入。建置只收錄明確列出的擴充功能檔案，不會打包網站資料、登入設定、測試或整個程式庫。

表內版本是 manifest 的載入門檻；各瀏覽器的實際測試狀態見文末。

## Chrome

1. 在網址列開啟 `chrome://extensions`，開啟「開發人員模式」。
2. 按「載入未封裝項目」，選擇已解壓的 `chrome` 資料夾；該資料夾內應有 `manifest.json`。
3. 如瀏覽器要求網站存取權，授予下方列明的網站及播放器網域。
4. 重新整理已開啟的 Umininn TV 頁面，才會注入新控制列。

更新至 0.1.6 時：

1. 解壓新 `chrome.zip`，用內容覆蓋原本載入的同一個 `chrome` 資料夾。
2. 開啟 `chrome://extensions`，找到此擴充功能，按重新載入，確認版本顯示 `0.1.6`。
3. 回到原網站，按 **F5** 重新整理，再按「🎚 播放控制」。

ZIP 不是 Chrome 商店安裝包。[Chrome 官方載入說明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)

## Edge

1. 在網址列開啟 `edge://extensions`，開啟「開發人員模式」。
2. 按「載入解壓縮」，選擇已解壓的 `edge` 資料夾。
3. 授予所列網站的存取權，再重新整理 Umininn TV。

更新時，先用新包覆蓋原資料夾，在 `edge://extensions` 手動重新載入此擴充功能，確認版本顯示 `0.1.6`，再回原網站按 **F5**。[Edge 官方載入說明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)

## Firefox

1. 使用 Firefox 140 或以上，開啟 `about:debugging#/runtime/this-firefox`。
2. 在「此 Firefox」按「暫時載入附加元件」，選取已解壓 `firefox` 資料夾中的 `manifest.json`。
3. 到 `about:addons` 查看此擴充功能的權限，確認網站及播放器網域的存取權已開啟，再重新整理直播網站。

這是未簽署的臨時擴充功能；關閉及重啟 Firefox 後會移除，需要再次載入。改副檔名為 XPI 並不會變成可永久安裝的已簽署版本。更新時，先用新包覆蓋原資料夾，在 `about:debugging` 按「重新載入」，確認版本顯示 `0.1.6`，再回原網站按 **F5**。Firefox 使用 MV3 背景 scripts，Chrome 及 Edge 使用 MV3 service worker。[Firefox 臨時安裝說明](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/)、[背景腳本相容性](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background)

Firefox 127 起，正常安裝會顯示並授予要求的主機權限，但使用者仍可撤回；臨時載入不會完整模擬正常安裝時的權限提示。控制列未出現或播放器無回應時，請先查看附加元件權限，再重新整理，不要將「臨時載入成功」當作所有跨網域權限已驗證。[Firefox MV3 權限說明](https://extensionworkshop.com/documentation/develop/manifest-v3-migration-guide/)

## 使用與限制

在原網站 `https://umininn-gh.github.io/tv/` 開始觀看後，可直接按頂部「↻ 偵測恢復」檢查一輪，或按 18px「🎚 播放控制」開啟獨立選單，使用同一按鈕、全部／逐台聲音控制及逐台「恢復播放」。原有「全部靜音／全部開聲」按鈕會由擴充功能接管，避免原網站以重新載入 iframe 切換聲音。安裝後已開啟的頁面須重新整理一次。

如控制連線逾時或已中斷，可按「↻ 偵測恢復」重新檢查一輪。仍未恢復時，確認擴充功能已載入及相關主機權限已授予，再重新整理網頁。

「開始觀看」會對本輪各台就緒後執行一次檢查／恢復，不必等齊其他台；也可自行按「↻ 偵測恢復」或逐台恢復。瀏覽器若因自動播放政策、平台限制或來源錯誤拒絕播放，仍需在播放器內親自按播放；擴充功能不會繞過限制，也不能修復失效串流。音量設為零與靜音是不同狀態；平台可能稍後改寫聲音設定。

固定播放器網域的可見 HTML 影片是預計控制範圍，實際支援須逐台測試。播放器可能使用巢狀 iframe、不同網域、特殊媒體介面或封閉的 Shadow DOM，因此有權限不等於每台必定支援。任意 BS 網址、未知 iframe 網域及未授權網域會顯示或視為不支援，不會自動擴大權限。

## 權限與資料

網站控制列只注入原網站的首頁及管理頁，並提供 `localhost`／`127.0.0.1` 指定路徑供本機測試。影片腳本只注入以下固定 HTTPS 主機：

- `player.twitch.tv`
- `player.kick.com`
- `ok.ru`
- `www.youtube.com`、`youtube.com`
- `www.youtube-nocookie.com`、`youtube-nocookie.com`
- `player.angelthump.com`
- `goodgame.ru`、`player.goodgame.ru`

`host_permissions` 依上述固定主機授權；瀏覽器對主機權限的路徑部分不作限制，實際控制列注入仍由 `content_scripts.matches` 的具體路徑限制。外站影片腳本會在匹配的 iframe 執行，背景程序只轉送來自已核准網站分頁的控制指令。它不要求全網站存取、分頁資料、cookies、debugger、網絡攔截或動態腳本注入權限。

程式碼全部隨包提供，不下載遠端程式碼、不使用 `eval`，不傳送收集資料至外部伺服器。擴充功能的指令與媒體狀態在本機瀏覽器內傳遞。此版不保存控制偏好；重新載入後需重新調整。Firefox manifest 宣告不收集資料；播放器網站原有的連線及資料處理仍由各平台負責。
